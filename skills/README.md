# Unified agent skills

A modular instruction library assembled from **Agency Agents**, **gstack**, **ECC**, and **Andrej Karpathy Skills**. It preserves actual procedures, checklists, examples, domain expertise, and failure handling, with per-file provenance. The downloaded source repositories remain read-only.

## Start here

1. Read [the compatibility contract](COMPATIBILITY.md). It governs composition, source-specific conflicts, and runtime prerequisites.
2. Apply the four [core principles](#cross-cutting-principles) proportionately to coding work.
3. Select one workflow and only the specialist/language/framework skills needed for the task.
4. Load references when the selected procedure calls for them. A “complete methodology” link is required reading, not a summary substitute.
5. Record actual verification results and missing prerequisites before claiming completion.

Use [manifest.json](manifest.json) for recursive discovery, source-scoped aliases, related skills, resources, and workflow handoffs. Nested directories are not automatically registered with any agent host. Use the supplied catalog rather than loading every SKILL.md into context.

## Workflow map

```text
Idea → Clarify → Plan → Architecture → Implement → Test
                                                 ↓
Reflect ← Monitor ← Ship ← Document ← Verify ← Review
```

The feature workflow combines gstack product/engineering planning, ECC implementation and verification, and specialist review. Stages are conditional on scope and authorization. Documentation can require a second pass after landing; deployment and monitoring require their actual runtimes. Machine-readable `steps` list ordered handoffs for each composed workflow.

- [workflows/bug-fixing](workflows/bug-fixing/SKILL.md) — Diagnose a reproducible defect, make the smallest repair, and prove the repair.
- [workflows/code-review](workflows/code-review/SKILL.md) — Compose structural review, engineering checks, and constructive specialist feedback.
- [workflows/design-review](workflows/design-review/SKILL.md) — Combine design direction, accessibility-aware UX, and live visual verification.
- [workflows/documentation](workflows/documentation/SKILL.md) — Create task-appropriate documentation and reconcile it with implementation.
- [workflows/feature-development](workflows/feature-development/SKILL.md) — Develop a feature from clarified intent through evidence-based release and reflection.
- [workflows/multi-agent-development](workflows/multi-agent-development/SKILL.md) — Coordinate bounded specialist work with explicit ownership, handoffs, and verified integration.
- [workflows/refactoring](workflows/refactoring/SKILL.md) — Refactor within an explicit scope while preserving observable behavior.
- [workflows/release](workflows/release/SKILL.md) — Prepare, document, land, deploy, and monitor a verified change.
- [workflows/research](workflows/research/SKILL.md) — Search, evaluate, and synthesize evidence before recommending implementation.
- [workflows/security-review](workflows/security-review/SKILL.md) — Select a security assessment variant and preserve its evidence and execution boundaries.
- [workflows/tdd](workflows/tdd/SKILL.md) — Use tests to define behavior, implement minimally, then verify the resulting change.

Source-specific sequences remain intact: gstack office-hours → plan-ceo-review → plan-eng-review → review → QA → ship; ECC research → plan → gated implementation/TDD → review → verify → remember; Agency NEXUS discovery → strategy → foundation → build → harden → launch → operate. Parallelism is used only when available and compatible with ownership and verification independence.

## Duplicate and consolidation notes

Exact body duplicates share one skill. Same-name ECC commands route to canonical skills while keeping distinct command behavior in separate references. Gstack startup sections are factored into one selectively loaded protocol. Similar names across sources remain separate unless equivalence is demonstrated. Cross-repository composition occurs in workflow entrypoints, preserving named variants rather than concatenating long source files.
